Section 06

Data Exfiltration

Staging, packing, transfer, rclone, and DNS tunnel evidence

Download PDF · Overview

Learning objectives

  • Describe the stage → pack → transfer exfil chain and artifacts at each step
  • Use MFT/USN and Hayabusa to time-box staging and tool use
  • Prove rclone-based exfil via config, cmdline, and Prefetch
  • Recognize DNS tunneling indicators and why adversaries use DNS

Exfil chain

Adversaries may move data in three beats: stage (collect into a folder), pack (zip/7z/rar, often encrypted/passworded), transfer (DNS, HTTP, cloud sync tools like rclone, or other channels). IR should prove each beat when possible.

PhaseHost artifactsNetwork artifacts
StageNew directories; large file creates in MFT; archive tools PrefetchInternal SMB/copy bursts
Packarchive.exe / 7z / rar command lines (4688); encrypted containersUsually still internal
Transferrclone/curl/custom beacon cmdline; rclone.confEgress to cloud/DNS/HTTP C2; large uploads

MFT & MFTECmd

The Master File Table records file metadata. Using MFTECmd (and USN Journal where available) analysts reconstruct create/modify/delete sequences and build timelines of staging folders — even when files were deleted after exfil.

  • Look for bursts of file creates in unusual paths (Temp, Public, hidden shares)
  • Note delete/rename around the transfer time — cleanup tradecraft
  • Combine MFT bodyfile with EVTX for process attribution

Hayabusa triage

Hayabusa turns Windows event logs into a Sigma-oriented timeline. Useful rule categories for exfil-related investigations include:

  • Process execution / suspicious command lines
  • PowerShell activity
  • Service install / scheduled task creation (prep for long-haul exfil)
  • Credential dumping detections (often precedes data theft)
  • Sigma rule hits stacked by frequency and severity

rclone — detection focus

Adversaries may use rclone to push staged data to cloud storage. Defenders prove use via:

ArtifactLocation / sourceValue
Config file%APPDATA%\\rclone\\rclone.confRemotes, provider, sometimes token material — isolate carefully
Process create4688 / Sysmon 1 cmdlineShows sync/copy and destination remote name
Prefetchrclone.exe Prefetch on clientsExecution evidence even if binary removed
NetworkProxy/firewall to S3/GDrive/etc. APIsVolume + timing vs staging

DNS tunneling — detection focus

Adversaries may encode data in DNS queries to bypass HTTP proxies when DNS resolution is allowed outbound. Prove with DNS telemetry + process evidence — not DNS alone.

  • Burst of nslookup or unusual resolver clients
  • Long, high-entropy, or Base64/Base32-like subdomain labels
  • Many unique subdomains under the same parent domain
  • Process attribution: which binary issued the queries (Sysmon 22 / EDR / memory netscan)
  • Volume far above baseline for that host/user

How do I prove exfil?

  • Timeline staging folder via MFTECmd → packing cmdline 4688 → transfer tool cmdline + egress logs
  • For rclone: conf + 4688 + Prefetch + cloud provider access logs if available
  • For DNS: DNS logs (encoded labels, burst, shared apex) + process that owns queries
  • Quantify business impact: which files (names/hashes from MFT) left the environment

Common exam traps

  • Calling any ZIP creation 'exfil' without transfer evidence
  • Ignoring encrypted archives (still prove stage+pack+egress metadata)
  • DNS tunneling conclusions without process attribution
  • Forgetting USN/MFT for deleted staging directories
  • Missing rclone.conf while hunting only for the EXE name

Lab takeaways

From Lab 4-2 — Data exfiltration
  • Separate retained older persistence from new staging by date/time before blaming "patient zero" on the burst.
  • Hayabusa: 4688 row count ≠ Proc Exec event count (one event → many rules). Burst vs quiet window as a rate; launch rate ≠ DNS packet rate.
  • Staging: encrypted archive; hash members vs staged files; keep compressed size ≠ source bytes. DNS chunk reconstruct offline — do not resolve live.
  • Upload intent: curl + PowerShell history as two independent sources. Report staged / compressed / received / delivered as separate numbers.
Quick reference
  • Chain: stage → pack → transfer
  • MFTECmd for file timeline / deleted staging
  • Hayabusa: exec, PS, service, task, cred-dump Sigma
  • rclone: %APPDATA%\\rclone\\rclone.conf + 4688 + Prefetch
  • DNS tunnel: bursts, encoded labels, same parent, process proof

Mini self-check

Try answering without looking back. Expand each item for the answer.

Q1. What are the three beats of a typical exfil chain?
A1. Stage → pack → transfer.
Q2. Where is the usual user-level rclone configuration path on Windows?
A2. %APPDATA%\\rclone\\rclone.conf
Q3. Name two DNS tunneling indicators beyond 'lots of DNS.'
A3. Long/encoded subdomain labels; many unique labels under one parent; nslookup bursts; mismatch with baseline; tied to a suspicious process.
Q4. How does MFTECmd help after adversaries delete a staging folder?
A4. MFT/USN metadata can still show create/delete/rename history and names/paths for timeline reconstruction.
Q5. Why might adversaries prefer DNS for transfer?
A5. To bypass HTTP proxies/firewalls when DNS queries are permitted outbound.
