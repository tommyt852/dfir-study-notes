Section 08

Incident Response

NIST phases, seven layers, and evidence-first practice

Download PDF · Overview

Learning objectives

  • Recite NIST IR phases and explain why containment comes early
  • Apply the seven response layers without mixing cause and damage
  • Order evidence collection by volatility and preserve chain of custody
  • Take correct account and network actions under pressure

NIST IR phases

PhaseGoalExample activities
1. PreparationBe ready before incidentsPlaybooks, logging, contacts, golden images, retainers
2. Detection & AnalysisKnow it is real and scopedAlert triage, IOC validation, timeline, impact estimate
3. ContainmentStop the bleedingIsolate hosts, block IOC, disable accounts, network ACLs
4. EradicationRemove causeDelete persistence, rebuild, patch exploited vuln
5. RecoveryRestore safelyRestore from clean backups, monitor, staged reconnect
6. Lessons LearnedImprovePostmortem, detection gaps, training, control upgrades
Contain first
  • Once you understand enough to act without destroying critical evidence needlessly, contain.
  • Do not wait for perfect root-cause analysis while adversaries still have access.
  • Balance: quick containment vs preserving volatile memory — plan both in the playbook.

Seven layers of response

LayerActions
NetworkIsolate VLAN/host; block IOC IPs/domains; sinkhole; disable VPN routes as needed
EndpointCollect (memory/logs/disk triage); analyze; remove persistence; reimage if required
UserCommunicate phish context; password resets; awareness; verify unusual user actions
ApplicationDisable abused apps/features; rotate app secrets; patch; take web app offline if shelled
AccountDisable compromised accounts; reset creds; revoke sessions/tickets; review privileges
EvidenceMemory → logs → disk; hash; chain of custody; legal hold
RecoveryRestore services; heightened monitoring; validate clean before trust

Cause vs damage

Keep two questions separate: How did they get in / stay in? (cause — vulnerability, phish, persistence) versus What did they touch or steal? (damage — data, systems, fraud). Eradication targets cause; business reporting needs damage. Mixing them muddies priorities.

Evidence order & custody

  • Memory first (when relevant) — injection, fileless, credentials, encryption keys
  • Then logs (volatile rotating buffers, remote SIEM copies)
  • Then disk (full image or targeted KAPE/triage)
  • Document: who collected, when, tool/version, hashes, storage location, transfers
  • Chain of custody forms for evidence that may enter legal proceedings

Account response checklist

  • Disable or lock clearly compromised accounts
  • Reset passwords / rotate keys; revoke Kerberos tickets and refresh tokens
  • Review group membership and privileged roles (especially Domain Admins)
  • Inspect authentication logs (4624/4625, Azure/M365 sign-in) for parallel sessions
  • Watch for adversary recreation of accounts or new API tokens

How do I prove the incident is contained?

  • No further C2 from fleet hunts (Velociraptor / EDR) after blocks
  • Persistence inventories clean on previously affected hosts
  • Compromised accounts show no new authentications; resets completed
  • Monitoring rules fire on residual IOC tests (and you verify they work)
  • Business services restored from known-good sources with elevated watch

Common exam traps

  • Skipping containment until full malware RE is done
  • Reimaging before memory capture when fileless activity is likely
  • Resetting passwords without revoking existing tickets/sessions
  • Focusing only on the patient-zero host and missing lateral movement
  • Declaring recovery complete without lessons-learned / detection improvements
Quick reference
  • NIST: Prep → Detect/Analyze → Contain → Eradicate → Recover → Lessons
  • Contain first (when safely possible)
  • 7 layers: network, endpoint, user, app, account, evidence, recovery
  • Evidence: memory → logs → disk + chain of custody
  • Separate cause from damage; rotate creds AND revoke sessions

Mini self-check

Try answering without looking back. Expand each item for the answer.

Q1. List the six NIST IR phases in order.
A1. Preparation; Detection & Analysis; Containment; Eradication; Recovery; Lessons Learned.
Q2. Which phase should generally begin as soon as you can act safely?
A2. Containment.
Q3. Name the seven response layers.
A3. Network, endpoint, user, application, account, evidence, recovery.
Q4. What is the preferred evidence collection order by volatility?
A4. Memory → logs → disk (then maintain chain of custody).
Q5. Besides resetting a password, what account action is often required after Kerberos exposure?
A5. Revoke tickets/sessions (and review privileges / auth logs); disable the account if appropriate.
