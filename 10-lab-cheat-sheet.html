E Memory forensics / Volatility

14 — Boot time + ProfileList vs sessions

windows.info does not report when the machine last booted. The System process (PID 4) is created at boot and runs until shutdown, so its creation time is the boot time.

vol -f <memory.raw> windows.info
vol -f <memory.raw> windows.pslist

Use pslist (or pstree) to read PID 4 / System create time.

ProfileList vs windows.sessions

They do not answer the same question:

Plugin / keyAnswers
ProfileList (HKLM\...\ProfileList)Every account that has ever logged in — historical record
windows.sessionsWho was logged in at the moment of capture
 
vol -f <memory.raw> windows.registry.hivelist
vol -f <memory.raw> windows.registry.printkey \
  --key "Microsoft\Windows NT\CurrentVersion\ProfileList"
vol -f <memory.raw> windows.sessions
vol -f <memory.raw> windows.pstree

15 — pslist vs psscan vs pstree

PluginWhat it does
windows.pslistWalks the active process list the way the OS does. Fast and accurate for anything running normally.
windows.psscanScans raw memory for process structures instead of trusting the list. Finds processes that have exited, and processes deliberately unlinked from the list to hide them.
windows.pstreeShows the same processes as a parent/child tree. Most problems show up here, because malware often has a parent process that makes no sense.

Exam tip: pslist ≠ psscan → look for hidden or exited processes (including DKOM-style unlink). Use pstree to spot impossible lineages.

16 — cmdline, dlllist, getsids, handles

PluginWhat it showsWhy it matters
windows.cmdlineFull command line each process was launched withEncoded or obfuscated arguments are a strong indicator
windows.dlllistModules (DLLs) each process has loadedA networking DLL inside a process that has no reason to talk to the network is a well-known indicator
windows.getsidsSecurity identifiers (SIDs) a process holds — whose authority it runs underA normally unprivileged program running as SYSTEM means privilege escalation happened. SID S-1-5-18 is the built-in SYSTEM account (highest local privilege)
windows.handlesOpen objects a process holds: files, registry keys, named pipesPipes are one way separate malware components talk to each other on the same host

17 — netscan + malfind

windows.netscan

Recovers TCP and UDP endpoints, including sockets already closed by capture time. Shows local/remote address, port, connection state, and owning PID.

windows.malware.malfind

Flags memory that is executable and writable but backed by no file on disk. That combination is the signature of injected or reflectively-loaded code. The plugin prints a hexdump of the first bytes so you can see whether they begin 4D 5A (MZ).

False positives

Some legitimate software allocates RWX memory genuinely — anything with a JIT compiler (browsers, .NET runtime).

Interesting hit = RWX and MZ header and a process that has no reason to be doing it.

Treat malfind as leads to check, not conclusions to report.

18 — windows.modules vs windows.driverscan

These plugins do not report the same kind of thing.

PluginWhat it walksHow things are named
windows.modulesKernel’s list of loaded module imagesAs files — ntoskrnl.exe, hal.dll, Path under \SystemRoot\system32\
windows.driverscanMemory for driver objectsIn the device namespace — \Driver\HTTP, \Driver\00000311

One image can own several driver objects, and scanning finds the same object more than once.

What does / does not prove

  • Comparing the two counts proves nothing — they count different kinds of thing.
  • Comparing the two name lists proves nothing — ntoskrnl.exe and \Driver\HTTP are not in the same namespace; no name will match.

The comparison that means something

Map by address: take each driver object’s Start from driverscan and find the module in modules whose Base … Base+Size range contains it.

A driver object whose Start falls inside no loaded module is worth investigating — something is executing in kernel space that the module list does not account for.

Lab scope note: full address mapping may be beyond a day’s exercise; still run both, record counts, and state clearly what the check does and does not support.

20 — vadinfo: hollowing vs reflective

Two columns do the work, not one.

windows.vadinfo lists a process’s memory regions and, for each one, whether it is backed by a file on disk. That separates file-backed code from private code.

It does not separate process hollowing from reflective loading, because both are private. For that you also check whether the main image region is still intact.

Read both before you name a technique.

24 — MFTECmd

Eric Zimmerman MFT parser — used for $MFT / $J (USN) timelines, create/modify/delete, and checking 0x10 vs 0x30 timestamps.

Typical lab path:

C:\Training\Tools\EricZimmerman\MFTECmd.exe

Pairs with: Timeline Explorer, AmcacheParser, Hayabusa.

Quick exam anchors
  • Static order: hash → file → entropy/imphash → imports → sandbox lineage
  • Dirty hive → collect hive and transaction logs
  • Native dump EXE → no PS 4104; hunt 4688 / Sysmon 1 cmdline IOCs
  • DCSync remediation → domain-wide reset + krbtgt ×2
  • pslist ≠ psscan; malfind = leads (RWX+MZ+odd process)
  • modules vs driverscan → map by address, not name/count
  • vadinfo: private vs file-backed; both hollow + reflective are private
  • Timestomp lead: SI (0x10) vs FN (0x30) mismatch
