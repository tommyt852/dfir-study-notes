Learning objectives

  • Recall the full DFIR topic map and how domains connect
  • Map 'how do I prove X?' workflows to artifacts and Event IDs
  • Distinguish detection evidence from attacker tradecraft
  • Prioritize IR phases: contain first; memory before disk
Scope reminder
  • This material covers detection, artifacts, and incident response only.
  • Attacker actions are phrased as 'adversaries may…' then pivot to evidence.
  • Tool/command names appear as IOC strings / exam knowledge — not how-to guides.

1. Malware Analysis

Static analysis

  • FLOSS — recovers decoded / stack / obfuscated strings adversaries try to hide
  • strings hunt — URL, IP, domain, registry key, file path, mutex (IOC material)
  • PE header — tools: file, readpe, pefile, objdump; compile time often fake; inspect sections, imports, entry point
  • Entropy >7 — often packed/encrypted (heuristic only; not proof)

Dynamic / C2

  • Reputation: Hybrid Analysis, VirusTotal (score, AV labels, family, indicators)
  • RE: IDA, Ghidra, x64dbg; sandboxes: Any.Run, Hybrid Analysis, Joe Sandbox
  • C2 channels to recognize: HTTP, HTTPS, DNS, loopback, named pipe, beaconing patterns

2. Triage & Collection

  • Velociraptor — collection, hunt, live response, artifact packs
  • KAPE Target = collect: MFT, Event Logs, Registry, Prefetch, Amcache
  • KAPE Module = parse: MFTECmd, EvtxECmd, RECmd

Deep dive →

3. Credential Dumping — Detection Only

  • LSASS holds NTLM hashes, Kerberos material, tickets, and sometimes cleartext passwords in memory
  • SAM dump requires SYSTEM hive for decryption — look for both files as evidence of intent
  • Well-known credential-tool module strings (e.g. sekurlsa::logonpasswords) are IOC hunt strings, not recipes
  • Prove dump: Event 4688 (suspicious Process Command Line), Sysmon 10 (Process Access → lsass.exe), presence of lsass.dmp, anomalous handle access
  • DCSync: Security Event 4662 with replication rights GUIDs; unexpected account; NTDS hashes without interactive DC logon; correlate with 4624 Type 3 for source IP

Deep dive →

4. Persistence

  • OS: service, scheduled task, Run key, Startup folder, WMI Filter+Consumer+Binding
  • Memory-only (reflective DLL / injection) — gone after reboot; disk persistence survives
  • Detect: 4698 (task created), 7045 (service installed), Sysmon, Autoruns anomalies, timeline
  • Always read: command line, path, creation time, account context

Deep dive →

5. Memory Forensics

  • Injection clues: RWX permissions, private memory, MZ header in unexpected regions
  • Process hollowing: legitimate process name with malicious memory map
  • Volatility/MemProcFS: pslist vs psscan (hidden/exited/DKOM), pstree, cmdline, dlllist, netscan, malfind
  • malfind: PAGE_EXECUTE_READWRITE + private + MZ; dump suspicious regions for further analysis

Deep dive →

6. Data Exfiltration

  • Stage → pack (zip/7z/rar/encrypted) → transfer (DNS, rclone, HTTP, cloud)
  • MFT via MFTECmd: create/modify/delete/timeline/USN Journal
  • Hayabusa: Proc Exec, PowerShell, Service Install, Scheduled Task, Cred Dumping, Sigma
  • rclone evidence: %APPDATA%\rclone\rclone.conf, 4688 cmdline, Prefetch, destination logs
  • DNS tunnel: nslookup bursts, encoded subdomains, Base64/Base32-like labels, same parent domain + process evidence; motive = bypass proxy when DNS is allowed

Deep dive →

7. Web Logs

  • Apache common/combined fields; IIS W3C — #Fields order can change; always parse header
  • Filter by URI, status, IP, method, request id, timestamp
  • Web shell chain: HTTP request → IIS w3wp.exe → cmd/powershell child
  • Trap: HTTP 200 ≠ successful attack; request ≠ execution — correlate with process creation

Deep dive →

8. Incident Response (NIST)

  • Phases: Preparation → Detection & Analysis → Containment → Eradication → Recovery → Lessons Learned
  • Contain first once scope is understood enough to act safely
  • Seven layers: network, endpoint, user, application, account, evidence, recovery
  • Separate cause from damage; evidence order: memory → logs → disk; maintain chain of custody
  • Accounts: disable, reset credentials, review privileges and authentication logs

Quick reference
  • Contain early; acquire memory before reboot when possible
  • HTTP 200 ≠ web shell success; correlate process creation
  • Entropy >7 = hint of packing, not proof of malice
  • 4662 alone is noisy — filter replication GUIDs + non-DC subject + 4624 source
  • Memory-only persistence vanishes on reboot — document before power-off
  • Always: cmdline + path + time + account = four-tuple for every persistence find

Mini self-check

Try answering without looking back. Expand each item for the answer.

Q1. Name two artifacts that help prove LSASS was dumped without relying on antivirus alerts.
A1. Sysmon Event 10 ProcessAccess targeting lsass.exe; Security 4688 with suspicious dump-related command lines; presence of an lsass.dmp (or similar) file; anomalous handle access patterns.
Q2. Why must you correlate 4662 with 4624 when investigating possible DCSync?
A2. 4662 shows directory object access (including replication rights) but usually not the source IP; 4624 with the same Logon ID (often Type 3) provides the network source — critical to see if it is a non-DC host.
Q3. What is the difference between a KAPE Target and a KAPE Module?
A3. Target = what to collect (MFT, EVTX, Registry, Prefetch, Amcache). Module = how to parse collected data (MFTECmd, EvtxECmd, RECmd).
Q4. Why is HTTP 200 insufficient to prove a web shell executed?
A4. A 200 only means the web server returned OK for the request; it does not prove server-side code ran a shell. Prove execution via child processes of w3wp.exe (cmd/powershell) and on-disk web shell files.
Q5. List the NIST IR phases in order and state which action comes first once you can safely act.
A5. Preparation → Detection & Analysis → Containment → Eradication → Recovery → Lessons Learned. Contain first (once scope allows safe action).
